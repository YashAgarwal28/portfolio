# Yash Agarwal: Portfolio

Static portfolio site (plain HTML, CSS, JS; no build step). Live at https://yashagarwal28.github.io/portfolio/

## Update content
- **Text, projects, skills, career:** edit `index.html` (each section has an `id`: about, what, career, work, skills, contact).
- **Add a project:** copy an `<article class="card proj">` block inside `#projects` and change the number, title, text, chips and preview.
- **Colors/spacing:** edit the variables at the top of `styles.css`.
- **Resume:** replace `assets/Yash_Agarwal_Resume.pdf` (keep the same file name so the three resume buttons keep working), then redeploy.

## Preview locally
Open `index.html` in a browser, or run `python -m http.server` in this folder.

## Deploy
Hosted with GitHub Pages from the `main` branch root of the `portfolio` repo. Pushing to `main` updates the site in about a minute.

## Notes
No client data, internal tool links or phone number are published here. Original design; it follows the general section flow of common developer portfolios but copies no third-party code or assets.

## Hero effect (full-viewport head tracking) and motion system
- `assets/char/` holds 64 pre-rendered head-angle frames (`f0..f63.webp`, 1280x720) plus `center.webp` (eye contact), about 1.8 MB in total. First paint needs only `center.webp` (about 35 KB); the rest stream in afterwards.
- One shared motion system drives every section: `data-reveal` (fade/slide in, staggered by `data-stagger`), `data-tilt` (3D card tilt), a spotlight on cards, a self-drawing career timeline, hero depth parallax and a scroll-progress bar. All use only `transform`/`opacity`, and all share the tokens at the top of `styles.css`.
- The page is static by default. `script.js` runs a quick draw benchmark and only then adds class `fx` to `<html>`. A runtime guard switches effects off if frames keep dropping. Visitors can also use the "Effects" switch (bottom-left, bottom-right on phones); the choice is remembered in `localStorage` (`ya-fx`).
- URL overrides: `?fx=high` (force on and clear the saved choice), `?fx=low` (force off), `?lite` (off for this visit), `?debug` (exposes `window.__ya`).
- Touch devices get a static portrait; frames load only after the first touch-drag on it. `prefers-reduced-motion` and data-saver/low-end devices get the static portrait and no animation.
- To rebuild frames from new source images, run `build_frames.py` (kept outside this folder).
- Head accuracy: `assets/char/map.json` stores each frame's measured eye position and gaze direction (generated by `calibrate_map.py`). The tracker picks the frame that really looks toward the cursor, wakes on scroll as well as mouse movement, and falls back to eye contact when no frame looks that way (the current video has no downward-looking footage).
- 3D response: besides picking the closest real pose, the head layer pitches forward when the cursor is below the face (and back when above) with a slight yaw and drop, so it reacts to mouse movement and scrolling even where the footage has no matching pose (the video has no downward-looking frames). A new video with full coverage would improve realism.
- Content structure: "What I do" = 6 category cards; Education and Certifications = one full-width row each; Projects = one full-width card each (role, key functionality, chips, illustration); Skills = one row per category with markers for used at work / used in projects / foundational.
